# 9. OpenFOAM case walkthrough

## 9.1 Case anatomy

An OpenFOAM case separates initial/boundary fields, physical models, and
numerical controls:

```text
baseline/
├── 0/                  Initial and boundary fields
├── constant/           Fluid properties, turbulence, MRF, mesh
└── system/             Mesh generation, schemes, solution, runtime
```

Generated `constant/polyMesh`, time directories, and `postProcessing/` are
runtime products rather than hand-authored input dictionaries.

## 9.2 `0/`: fields and boundary conditions

The baseline `U` internal field is `(1.92 0 0)` m/s. At the selected
$n=10$ rev/s and $D=0.24$ m, this corresponds to $J=0.8$:

$$
J=\frac{1.92}{10(0.24)}=0.8.
$$

`p` is kinematic pressure for incompressible `simpleFoam`; it is not absolute
pressure in pascals. `k`, `omega`, and `nut` initialize the RANS model.

The inlet and outlet, outer slip walls, and propeller wall must be checked
against the intended physical configuration. A dictionary that parses is not
proof that its boundary conditions represent a propeller test.

The propeller patch uses `noSlip`. In an MRF zone, `MRF.correctBoundaryVelocity`
sets included rotating-wall patch values to $\boldsymbol{\Omega}\times\mathbf{r}$;
the v2512 `simpleFoam/rotatingCylinders` tutorial uses `noSlip` for the
rotating inner wall. Do not prescribe an additional mesh-motion velocity on a
stationary MRF mesh unless the selected wall treatment explicitly requires it.

## 9.3 `constant/`: physical model

- `transportProperties` sets Newtonian kinematic viscosity $\nu$.
- `turbulenceProperties` selects RANS and `kOmegaSST`.
- `MRFProperties` gives the rotating cell zone, origin, axis, and angular speed.
- `triSurface/propeller.stl` is generated geometry input.

For incompressible force integration, the `forces` function object uses
`rho rhoInf` and `rhoInf 1000`. The field `p` remains kinematic; the force
object applies density to convert pressure contribution to dimensional force.

## 9.4 `system/`: numerical and run controls

| File | Role |
|---|---|
| `blockMeshDict` | Background hexahedral domain and boundary patches |
| `snappyHexMeshDict` | Surface refinement and snapping |
| `topoSetDict` | Creates the `rotor` cell zone |
| `fvSchemes` | Gradient, divergence, interpolation, and Laplacian schemes |
| `fvSolution` | Linear solvers, SIMPLE settings, and relaxation |
| `controlDict` | Solver, iteration limit, writes, function objects |
| `decomposeParDict` | Parallel partitioning configuration |

`endTime 1000` is an iteration limit in this steady solver, not 1000 seconds.
`deltaT` is retained in the dictionary syntax but is not physical transient
time for the `steadyState` formulation.

## 9.5 Current-case status, not a recipe to copy blindly

The current `snappyHexMeshDict` disables boundary-layer layer addition and
requests surface refinement level `(2 2)`. The mesh is a workflow test, not a
mesh-independence result. `checkMesh` reported one skew face with maximum
skewness 4.23, and the initial solver run was stopped at iteration 692.

Most importantly, the surface generated by `generate_geometry.py` is only a
coarse proxy and is not a closed full-section B5-75 blade. A valid OpenFOAM
execution on this surface is not a valid propeller simulation.

## 9.6 Safe execution sequence

From `04_MRF_Steady/baseline`:

```bash
./Allclean
./Allrun
```

`Allrun` generates the STL, creates the mesh, creates the MRF zone, checks the
mesh, and runs `simpleFoam`. Review each log before continuing:

```bash
grep -E 'Failed|FATAL|Mesh OK|End' log.checkMesh
grep -E 'Time =|Solving for|Sum of forces|Sum of moments' log.simpleFoam
```

Do not treat script exit status alone as convergence. The mesh quality, force
history, and independent verification still matter.
